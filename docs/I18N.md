# Internationalisation (English / Arabic)

The portal ships in **English** and **Arabic** (right-to-left). The language comes from the `locale` cookie,
which is set from the user's saved preference (`User.locale`) at sign-in or by the language switcher (header,
user menu, login page). Everything that is not user-entered data is translated.

## Where things live

| What | Where |
|---|---|
| Locale list, RTL, Intl locale (`ar-AE` = Arabic months, Western digits) | `src/i18n/config.ts` |
| Messages, one file per namespace and locale | `messages/en/<ns>.json`, `messages/ar/<ns>.json` |
| Typed message loader | `src/i18n/messages.ts` (keys are type-checked against the English files) |
| Server helpers: `getFormat()`, `serverT(ns)`, `translatorFor(locale, ns)` | `src/server/i18n.ts` |
| Client formatter hook `useFormat()` | `src/components/i18n/use-format.ts` |
| Formatting (dates, months, money, numbers) | `src/lib/format.ts` |
| Validation messages (our English Zod messages → Arabic) | `messages/ar/validation.json` + `src/server/validation-i18n.ts` |
| Parity test (same keys and placeholders in both languages) | `tests/unit/i18n-messages.test.ts` |

## How to translate a screen

- **Async server component / page**: `const t = await getTranslations("leave");` and
  `const f = await getFormat();`.
- **Non-async server component or client component**: `const t = useTranslations("leave");`, plus
  `const f = useFormat()` in client components (or `createFormat(useLocale())` in non-async server components).
- **Page title**: replace `export const metadata = { title: "…" }` with
  `export async function generateMetadata() { return { title: (await getTranslations("leave"))("meta.title") }; }`.
- **Services and server actions** (error messages, success toasts): `const t = await serverT("leave");`. It works
  outside a request too (worker, seed), where it falls back to English.
- **Status and enum labels**: use the shared `enums` namespace, e.g. `t("enums.leaveStatus.APPROVED")`, or the
  shared badges (`LeaveStatusBadge`, `RunStatusBadge`, `EmployeeStatusBadge`).
- **Generic words** (Save, Cancel, Search…, pagination, empty or error states) are in `common`.
- **Dates and money**: `f.date(d)`, `f.dateTime(d, tz)`, `f.month("2026-10")`, `<Money minor currency />` or
  `f.money(...)`. Don't call `formatDate`, `formatDateTime`, `periodLabel` or `formatMoney` for display.
- **Plurals**: ICU, e.g. `"{count, plural, one {# day} other {# days}}"`. Arabic uses the zero, one, two, few,
  many and other forms.

## RTL rules

- Use logical Tailwind classes (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`, `text-end`,
  `border-s`, `rounded-s` …), never `ml-`, `left-` and the like. A codemod already converted the codebase.
- Direction-bearing icons (chevrons, arrows, "back" or "next") get `className="rtl:-scale-x-100"`.
- Wrap values that must stay left-to-right inside Arabic text in `<span dir="ltr">`: IBANs, emails, phone
  numbers, employee numbers, codes and formulas.
- To centre something with `left-1/2 -translate-x-1/2`, keep `left` (centring is symmetric).

## Not translated (data)

Names, department, position, location and leave-type names, company details, notes and reasons typed by
users, and audit-log summaries (stored as text when the event happens) are shown as entered.
